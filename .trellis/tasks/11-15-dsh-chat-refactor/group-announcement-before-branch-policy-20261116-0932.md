项目：DS Bot。工作目录 /Users/yyj/Project/develop/ds-bot-release-stable/ds-bot。此群用于需求分析、开发、独立测试、审查和交付协调；收到具体任务后才开始实施。

协作：管理员先确认目标、验收标准、基线、负责人和写入范围，按需协调 Developer 实现、QA 独立验证、审查员独立审查；咨询可直接答复。并行工作须明确写集，保护已有未提交修改。冲突或关键证据缺失时暂停受影响步骤并报告。交接和验收须核对同一版本、完整差异、原始命令与结果，说明失败、限制和未覆盖项；发现问题后修复并复验。

项目约束：先读 AGENTS.md、相关设计与现有实现；只使用 DSH 已公开的插件接口，不修改 DSH 安装、用户 DSH 数据，不输出密钥，不手改生成的 client.js。测试使用项目隔离环境与 mock 模型，区分真实调用、模拟和未验证。代码变更按仓库要求运行 npm test、node scripts/build-client.mjs --check、npm run lint；index.js 或 src/host/ 变更另做 mock smoke 并清理自启进程。

提交、合并、推送、创建 PR、发布或部署须用户明确指示；不得将其他项目的专属授权带入本群。

验收与交接：每项结果标明执行者、基线与工作树、实际命令和退出状态，区分独立复跑、核对他人证据与未验证。派单回执、目标状态或成员自报本身不等于验收；管理员核对全部必选交付与证据后推进，缺项记录负责人及所需条件。无依赖的工作并行，复测和审查基于稳定交付版本；隔离验证条件不足时协调处理，避免改动开发工作树。目标分支与执行基线不同时，交付须说明分支差异和成果适用范围；迁移后在目标分支复验受影响的行为。

隔离验证：分别确认被测服务和调用工具的存储位置；截图或图片读取可能由当前会话工具保存附件，确认输出落在隔离环境后再使用会生成附件的工具。发现输出涉及用户 DSH 数据目录时停止相关操作，记录来源并报告管理员，不自行读取或清理该目录。

群内汇报尽量突出新增结论、证据位置、阻断与下一步；详细日志保留在交付材料中，避免重复粘贴。验收必选证据仍须完整记录。

检索与工具输出：已知文件优先直接读取；定位未知文件先限定工作区子目录和具体文件名，检查依赖或缓存时只查看所需包目录，避免递归枚举整个依赖或缓存树。调用前考虑工具的返回上限和临时结果位置；发生溢出时记录来源和位置，按约定处理，并缩小范围继续核实。

固定交付的指纹直接引用校验命令输出或机器生成的清单；发送前核对补丁文件与清单一致。发现不一致时保留原记录，并补充更正。

测试日志与证据：写入或输出前遮蔽令牌、会话凭据等敏感值，包括临时测试凭据，避免原值进入日志、请求记录和交付材料。若发现凭据进入隔离测试文件，停止扩散并按管理员约定处理，保留不含凭据的失败摘要、命令、时间和处置记录；涉及用户数据目录时遵循上述隔离约定。

接力交接：已获准的任务范围内，需要下一位成员行动时，在群内使用有效的 @ 提及管理员或已明确的接手成员，并说明证据、当前状态和待办；普通名字不构成点名。每项交接只作必要提醒；目标暂停或需要用户决策时，先由管理员协调，不自行恢复。
