# DS Bot 对话重构实施与验收计划

状态：规划。实施前按仓库流程读现有设计和 Trellis 指南；本任务未开始实现、发布或数据迁移。各阶段先验证关键行为，再推进下一阶段；阶段失败则保留现有实现并记录具体缺口。

## 0. 版本与隔离基线

- 记录候选 DSH 的确切版本和公开契约；基线为项目当前固定的 0.2.2-rc.1，候选为本机已安装及 npm next 的 0.2.2-rc.3。正式支持范围和升级时点由后续实际验证结果确定。
- 通过仓库的 dev/harness 和现有 test/harness-resolve.mjs 验证不同版本的依赖解析；真实交互验证使用独立 DSH 源码树、独立端口与 .dsh-test-<name> 数据目录、dev/mock-llm.mjs，不连接用户正在运行的 DSH 或使用其数据。
- 先核实可用 DSH 源码树满足 dev/bench.sh 的入口和 overlay 需求；已安装桌面包不等于该源码树。reset 会删除指定的隔离 bench 数据目录，使用前核实目标。完成后停止本次启动的 bench 和进程。
- 优先评估 DSH 的 Session 归档与工作树回收：在独立临时 Git 仓库和隔离 DSH_HOME 中，观察 DS Bot 换段归档旧 Session 后，新段是否保持对工作目录的引用；按需覆盖 retainOnArchive 设置和带忽略文件的工作树。预期：确认实际保留/清理条件及忽略文件影响，业务要求保留时制定依赖公开设置的处理方案。不可在用户现有工作树上做此验证。
- 参照安装版 DSH 的升级指南索引，核对与插件实际代码有关的附件错误码、Session.append 重载及 macOS 自定义浮层窗口区域。已有 [macOS 样式](../../../ds-bot/src/client/styles.js#L1113)显式为部分标题控件设置 no-drag；仍须逐个核实跨页头的自定义浮层，并在涉及布局时实测点击和拖动，不能仅凭升级说明认定现有控件失效。
- 产物：基线记录、隔离环境来源以及两个版本的对照清单。
- 通过条件：已有私聊、群聊和历史 fixture 在隔离环境中可重复打开；命令失败时先说明缺少的前置条件，暂停相关验证，不声称已通过。

## 1. 私聊最小可行性验证

- 盘点 [会话槽点注册](../../../ds-bot/src/client/index.js#L1083)中每项覆盖的真实用途；在独立工作分支依次尝试保留现有框架、恢复一项 DSH 原生节点。初选普通回复、过程和工具展示；每次只切换一类。
- 检查用户发言、Bot 回复、流式状态、工具过程/结果、图片、交互问题、错误、压缩信息、队列及停止。确认 Bot 名称、头像、role 标识、跳转目标及 turnTail 保持正确。若改输入或触发菜单，还需验证 steer、@成员/全体、对话引用、IME、草稿及附件；确认 Bot 菜单与普通 Agent 会话的候选项符合预期。
- 复用现有相关单测：test/chat-rows.test.js、test/tool-cells.test.js、test/composer-enter.test.js、test/queue-dock.test.js、test/blocking-question.test.js、test/at-menu.test.js 等，并用一次隔离 mock UI 流程验证真正的显示和发送；按改变范围选择相关测试。
- 通过条件：目标节点使用公开接口，基线和候选版本上显示与交互符合现有行为，且变更确实减少重复实现或修复明确兼容问题。原生节点缺少必需语义时保留当前节点，记录缺失的公开扩展点。

## 2. 群聊、账本与多 Bot 协作

- 在私聊验证通过后，逐项评估 group_relay 节点和群消息显示；保留独立群调度、群账本锚点和 group stop；保留 Bot pair 账本、送达状态以及权限与消息投递协议。
- 使用隔离 fixture 执行一条用户消息触发两位成员并行工作，先完成者立即显示，批次结算后派活者只被唤醒一次；群忙碌期间再次发言，检查成员状态、单人停止、全群停止、审批、刷新和重启恢复。核对消息顺序、唯一性、成员身份、锚点范围与实际投递状态；若改动账本或锚点，针对相同序号的两个锚点、长消息和账本领先状态文件的恢复场景复用或补充覆盖。
- 复用 test/groups.test.js、test/group-status.test.js、test/group-work.test.js、test/rounds.test.js、test/ledger.test.js、test/exchange.test.js；必要时补充能够覆盖新旧渲染边界的真实行为测试。
- 通过条件：用户发言只显示一次、群和私聊的 Bot 来源正确、旧 group_relay 结果与新锚点均能读取、独立群停止能结束对应工作。缺少公开数据接入点时保留群专用视图或节点，说明上游需求。

## 3. 跨段历史和兼容

- 使用现有跨段机制装载至少一个旧段和当前段；使用仓库旧格式 fixtures 验证旧 group-logs / group-lines 与旧工具结果路径。若改动交互卡，验证 ask_user、阻塞式 ask_user_question 和 show_view 的待答、提交、已答回放、失败重试及跨段保持；两种问答的行为分别验收。
- 复用 test/history.test.js、test/archived-parts.test.js、test/ledger.test.js；涉及跨段输入和卡片时按需复用 test/switch-keeps-input.test.js、test/card-hold.test.js、test/view-reply.test.js。观察加载较早历史、滚动定位、切换段和刷新后顺序。
- 通过条件：旧消息完整可读、顺序正确、边界无重复或遗漏，切换前后 Bot 身份与会话路由保持一致；若失败保留 EarlierParts 等现有实现。
- 验证回退时，保存升级后的隔离数据副本，核对旧插件和旧 DSH 能否读取切换后新增的 Session 事件、群账本及待完成工作。不得将单纯恢复升级前快照视作保留了升级后消息。计划默认不改变持久格式；如发现必须迁移，另行编写设计，覆盖一致性备份、切换游标、单一写入方、前后版本读取、迁移中断恢复与回退，并独立验收。

## 4. 削减内部耦合与可选嵌入

- 核对 [样式中的 DSH 内部结构选择器](../../../ds-bot/src/client/styles.js#L1090)，先查可公开使用的插槽与样式契约，逐项移除已无必要的覆盖；公开接口不足之处保留当前路径并记录可复现缺口。若更动输入触发源，依据公开文档确认全局 source 和 Session 自身过滤行为，不假设原生 source 支持逐 Session 遮蔽。
- 只有产品确需侧栏或多视图时才验证 conversation.content 工厂、SessionProvider 与 retain/release 组合；检查组件卸载、切会话、历史流以及断线恢复。retain 仅代表客户端引用保活。
- 通过条件：现有 Bot/Agent 模式、常用窗口尺寸和 DSH 视图工作正常，且没有依赖 DSH 安装目录的私有运行时组件。无公开替代时该项不强行改造。

## 5. 仓库质量门槛和交付

源文件放在 ds-bot/src/client/；运行 npm run build 生成 client.js，不手改生成文件。每个实际行为改动完成后按仓库要求执行：

~~~sh
npm test
node scripts/build-client.mjs --check
npm run lint
~~~

修改 ds-bot/index.js 或 ds-bot/src/host/ 时，额外在满足前置条件的隔离 DSH 源码树上运行仓库规定的 mock smoke，选取空闲端口并关闭进程。界面变更在隔离环境做最短真实交互验收，覆盖实际变动的消息、输入、工具、历史或群功能；涉及布局时核对明暗主题、窄屏及键盘操作。不默认对每个阶段重复全量 UI 验证。

最终交付包括：兼容版本记录、逐类迁移和未迁移理由、核心验证结果、具体上游缺口、对旧数据与回退的说明。独立桌面应用有自己的 DSH 固定版本和数据目录，其升级和平台验证单列，不以插件通过等同于桌面应用通过。dev/check.sh 的 desktop 路径是 Linux 脚本，不假设能直接完成 macOS 桌面验证。

| 私聊流式/工具/错误/问题/附件及队列 | 隔离 mock 基线 | 相同行为复核 | 受影响功能可见且可交互，身份与队列正确 |

| 桌面应用 | 仅按单独升级范围验证 | 仅按单独升级范围验证 | 明确平台、独立数据目录和实际结果 |

本表描述计划而非已完成的测试结果；同一版本上只执行与实际更改相关的最小验证，必要时扩大。
