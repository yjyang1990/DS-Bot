# DS Bot 新版 DSH 对话重构规划

## 目标

分析当前安装的 DeepSeek Harness 与 DS Bot 的会话及界面，制定可验证的插件重构方案，使 Bot 功能尽可能结合新版 DSH 的对话能力。此任务目前处于规划阶段。

## 用户需求

- 以当前最新 DSH 为基准，调查新增对话功能、界面和插件扩展能力，指出哪些可以直接复用，以及哪些仍需 DS Bot 实现。
- 保留长期 Bot 身份和配置、用户与 Bot 私聊、多 Bot 协作、群聊、工具与交互卡片、消息历史及正在进行的工作等已有能力。
- 比较现有实现与目标架构，给出分阶段、可回退的实施计划、验证方式和影响范围。
- 邀请项目内真实 Bot 团队参与规划，将可核实的实际意见与本次分析合并；界面若未显示创建时间，准确记录身份核实范围。
- 在项目中使用已初始化的 Trellis 保存本次规划。

## 约束

- 只使用 DSH 公开插件 API，不修改 DSH 本体或依赖安装目录内的私有文件运行。
- 客户端修改以 `ds-bot/src/client/` 为源，按现有构建流程生成 `client.js`。
- 保持现有团队与会话数据可读；涉及数据转换时提供备份、迁移与回退方案。
- 开发与验证使用隔离的测试工作区、独立 DSH_HOME 和 mock 模型，不使用用户运行中的 DSH 作测试。
- 当前只完成调查和规划；实现、提交及推送均不包含在本任务中。

## 验收标准

- [x] 记录当前安装版本、npm 发行标签及 DS Bot 测试/桌面应用固定版本。
- [x] 形成按能力分类的 DSH 与 DS Bot 功能对照，区分已核实接口、需验证的复用与缺失的扩展点。
- [x] 给出私聊、群聊、跨段历史与实时事件的边界和数据流，并覆盖旧数据读取与回退。
- [x] 形成有顺序的最小验证和实施计划；每阶段写明交付物、通过条件及失败时的处理。
- [x] 制定复用现有测试验证私聊、群聊、交互与历史的计划；实施时针对升级引入的行为补充必要验证。规划阶段未执行测试。
- [x] 邀请真实项目 Bot 团队参与规划，记录 Developer、QA、Reviewer 的意见及采纳情况。界面未显示创建时间，无法逐个确认最近创建的成员。
- [x] 保持任务为 `planning`，完成 `prd.md`、`design.md`、`implement.md`。

## 需要验证的决策

- 原生 DSH 会话视图是否通过公开 API 支持 Bot 群消息、消息身份与历史注入；若缺少对应扩展点，保留必要的 Bot 专用视图，并明确上游需求。
- 先验证已安装的 `0.2.2-rc.3`；`latest` 标签及旧版支持范围根据发行状态和兼容性验证决定。
- 桌面应用的 DSH 升级与插件集成需分别验证，是否在同一发布周期交付由后续范围决定。
